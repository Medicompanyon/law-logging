## 우선순위 2: PostgreSQL·ORM·환경변수 검증 기반 구축

- 관련 이슈: [#8 Foundation](https://github.com/Medicompanyon/law-logging/issues/8), [#3 Architecture](https://github.com/Medicompanyon/law-logging/issues/3)
- 권장 시간: 13:00-15:20 KST
- 목표: 합성 데이터만으로 로컬 DB를 실행하고 안전하게 연결·마이그레이션할 수 있는 최소 기반을 만든다.
- 구체적 구현 범위:
  - Docker Compose로 로컬 PostgreSQL 서비스를 구성하고 영속 볼륨 및 healthcheck를 추가한다.
  - TypeScript 친화 ORM을 선택해 연결 모듈과 최초 연결 검증용 마이그레이션을 만든다.
  - `.env.example`에는 자리표시자만 두고, 실제 환경 파일은 `.gitignore`로 차단한다.
  - 서버 시작 또는 빌드 시 필수 환경변수를 스키마로 검증하고, 값 자체를 출력하지 않는 오류를 제공한다.
  - 후속 #3의 모델 구현을 막지 않도록 마이그레이션·트랜잭션·테스트 DB 규칙을 문서화한다.
- 완료 조건:
  - 문서화된 단일 흐름으로 PostgreSQL 기동, 연결 확인, 마이그레이션 적용이 가능하다.
  - 필수 환경변수 누락 또는 형식 오류 시 비밀 값을 노출하지 않고 즉시 실패한다.
  - 환경 파일, DB 덤프, 로그가 커밋 대상에서 제외된다.
- 테스트 방법:
  - 깨끗한 로컬 DB에 마이그레이션을 적용하고 재실행 시 멱등성을 확인한다.
  - 잘못된 URL과 누락된 환경변수에 대한 단위 테스트를 수행한다.
  - `git status`와 비밀정보 스캔으로 실제 자격증명·개인정보가 추적되지 않는지 확인한다.
- 보안·개인정보 위험:
  - DB 접속 문자열, 비밀번호, 덤프가 저장소 또는 CI 로그에 노출될 수 있다.
  - 개발 DB를 외부 인터페이스에 불필요하게 공개하거나 약한 기본 자격증명을 운영에 재사용할 수 있다.
  - ORM 디버그 로그에 쿼리 매개변수나 개인정보가 기록될 수 있으므로 값 로깅을 기본 비활성화한다.
- 예상 차단 요소:
  - ORM 선택이 확정되지 않았다. 오늘은 마이그레이션 안정성, PostgreSQL 지원, Next.js 런타임 호환성을 기준으로 선택 근거를 남긴다.
  - 로컬 Docker 사용 불가 환경에서는 별도 PostgreSQL 접속값이 필요하므로 연결 계층을 교체 가능하게 유지한다.
